# 产品范围

## 定位

Onegit 面向 macOS 上同时处理多个 Git 仓库和 worktree 的使用场景。它基于 Onevra 构建，目标是承接日常工作中常用的仓库浏览与 worktree 切换需求，不以覆盖通用 Git 客户端的全部功能为目标。

本文记录产品方向，已实现范围见 [README](../README.md#当前阶段)。

## 已确认方向

| 方向 | 含义 |
| --- | --- |
| 以 worktree 为主 | worktree 是日常浏览与定位工作的主要单位。 |
| 多仓库一起管理 | 在同一个应用中汇集多个仓库，查看它们的工作状态。 |
| 侧边栏入口 | 侧边栏选择项目；不在应用层使用标签页在项目之间切换。 |
| worktree 标签页 | 项目内部以标签页展开该项目的全部 worktree，主仓库在首项；只有一个 worktree 时隐藏标签页。 |
| 仓库页面 | 标签页下方是工具栏，再下方分为项目侧边栏与内容区；内容区展示工作区改动、提交与分支。 |
| 按需状态 | 进入项目或手动刷新时读取状态，不持续轮询；具体状态字段仍可扩展。 |

项目父目录可由用户在设置中选择并保存；启动和更换目录时扫描一次有效 Git 项目，并按目录层级展示在侧边栏。扫描遇到有效仓库即停止向内遍历；可发现所选目录内、未被上层仓库包含的 linked worktree，侧边栏不自动纳入目录外的关联 worktree；选中项目后的 worktree 标签页会读取全部关联 worktree，不受父目录范围限制。

## 待确认的表述

“无用户操作”保留为原始要求，其具体含义尚待确认：可能指不提供 Git 写操作、无需手动刷新，或不涉及用户账号管理。当前实现不会自行执行 Git 操作；工具栏中的获取、拉取、推送、贮藏与切换分支只在用户点击时运行，不据此确定只读模式或账号体系的范围。

## 后续再定

worktree 标签页、工具栏与项目侧边栏是本轮已实现的结构；更细的实时状态字段、自动刷新时效与更完整的 Git 操作范围留待后续设计。
